# S1: Multi-user agent loop + raw log

## Goal

Demo: two users each chat through the CLI; the agent calls web search, web fetch, and reads and writes files in its own workspace; every event is stored per user; a new session remembers nothing (this slice has no memory at all).

## Out of scope

Memory (observations, facts, embeddings, retrieval), the eval framework (S2), background jobs, sandboxed code execution (S9), row-level security (S7), any web UI.

## What to build

### 1. Database (Alembic migrations)

- `users(id uuid, name, api_key_hash, created_at)`
- `sessions(id uuid, user_id, created_at)`
- `events(id bigserial, user_id, session_id, seq int, type, payload jsonb, created_at, redacted_at nullable)`
  - `seq` increases within a session; `(session_id, seq)` is unique
  - `type` is one of: user_message / assistant_message / tool_call / tool_result / error
- Trigger: forbid DELETE; allow UPDATE only when `redacted_at` goes from NULL to non-NULL and the payload is rewritten to a redaction marker in the same statement; reject every other UPDATE
- `llm_calls(id, user_id, session_id, module, model, input_tokens, output_tokens, cached_input_tokens, search_calls int default 0, cost_usd numeric, latency_ms, created_at)`
- Function `redact_event(event_id, user_id)`: implemented and tested in this slice; wired into the "forget" flow in S7

### 2. Scrubbing gateway `memagent/sanitize.py`

- Rules and regular expressions, synchronous, no LLM. Cover at least: common API key formats, values following `password` / `token` / `secret` (in English and Chinese spellings), PEM private key blocks, bank card numbers (Luhn check), 18-digit Chinese national ID numbers (check digit).
- Replace each hit with `[REDACTED:<type>]`; return the scrubbed text and hit counts.
- Single write path: `store.append_event()` scrubs internally before writing; workspace file writes go through it too.
- Decision (record it): the history sent to the model is rebuilt from the database, so the model also sees only scrubbed content. The cost: tasks that need a real password can't be done.

### 3. LLM client `memagent/llm/`

- Interface: `complete(messages, tools, model) -> LLMResponse` (text, list of tool calls, usage).
- One real provider implementation, OpenAI (Responses API), and one FakeLLM (returns scripted responses, for tests). The OpenAI-specific message and tool-call formats stay inside the provider module; the rest of the code only sees the project's own types.
- Model names come from environment variables (`AGENT_MODEL`, `SEARCH_MODEL`); none are hardcoded.
- Keep the price table in a config file (per-token prices per model, plus the per-search fee); compute `cost_usd` from usage; every agent call writes one `llm_calls` row with module `agent`.

### 4. Agent loop `memagent/agent/loop.py`

- Rebuild the session's message list from events → call the model → if it asks for tools, run them and write the results as tool_result events → call the model again → stop when there are no more tool calls, or at `max_steps` (default 10; when exceeded, write an error event and tell the user in one sentence).
- Tool exceptions are never raised; they are fed back to the model as a tool_result with `is_error`.
- Concurrent requests in the same session must be serialized: take a Postgres advisory lock keyed by session id.

### 5. Tools `memagent/tools/`

- `web_search(query)`: an interface + one real provider + a fake implementation. The real provider uses OpenAI's hosted `web_search` tool, called from inside the provider as a separate request with `SEARCH_MODEL`, limited to one search per call (use the API's tool-call limit if available; otherwise instruct it and verify the count of search calls in the response). It returns a short list of results (title, URL, snippet) as a normal tool result. Each call writes one `llm_calls` row with module `search` and the actual number of searches in `search_calls`. The agent loop executes `web_search` like any other tool; the hosted search tool is never given to the agent model directly (decision record: why).
- `web_fetch(url)`: httpx; timeout and maximum byte limits; HTML converted to plain text; reject private, loopback and link-local addresses (SSRF protection: resolve DNS first, then check; check every hop when following redirects).
- `workspace_list` / `workspace_read` / `workspace_write`: one directory per user at `data/workspaces/<user_id>/`; path traversal protection (after resolving, the path must stay inside that user's root); per-file size limit; written content goes through the scrubbing gateway.

### 6. API and auth `memagent/api/`

- Header `Authorization: Bearer <api_key>`; the database stores only a SHA-256 hash (randomly generated high-entropy keys don't need a slow hash; record this decision).
- `POST /sessions`
- `POST /sessions/{id}/messages`: returns the final reply and a summary of this turn's steps
- `GET /sessions/{id}/events`
- Accessing another user's session returns 404.

### 7. CLI `memagent` (Typer)

- `memagent user create <name>`: create a user and print the API key once
- `memagent chat`: start a new session and chat interactively, showing tool calls and this turn's cost

### 8. Tests (FakeLLM only, no spend)

- User isolation: A cannot read B's sessions or events (404)
- Tool loop: when a scripted FakeLLM keeps requesting tools, the loop stops within `max_steps` and leaves an error event
- Tool errors are fed back to the model instead of crashing
- Scrubbing: after storing a message containing a password, an API key and an ID number, the raw values cannot be found in the database
- Append-only: a direct UPDATE or DELETE on events fails; `redact_event` succeeds
- Path traversal and SSRF are blocked
- Every FakeLLM call writes an `llm_calls` row
- Concurrency: when two requests for the same session arrive at once, event seq values are contiguous with no duplicates

### 9. Configuration

- `.env.example` (committed) lists every variable with a placeholder: `OPENAI_API_KEY`, `AGENT_MODEL`, `SEARCH_MODEL`, `DATABASE_URL`, `MAX_STEPS`. The real `.env` is in .gitignore.
- One OpenAI key covers both the agent model and search. Tests must pass with no `.env` at all.

## Deliverables

- Code, with all tests passing and no ruff or pyright errors
- README: steps from a clean machine to the first conversation
- `docs/walkthrough/S1.md`: suggested reading order; the full code path of one message from the CLI through the API, the database and the model and back; the reason behind each key design choice
- At least 4 records in `docs/decisions/`:
  1. A hand-written agent loop vs. a framework
  2. An append-only raw log, and redaction as its only exception
  3. Scrub before persisting (including the trade-off that the model also sees only scrubbed content)
  4. SHA-256 rather than bcrypt for API keys
  5. Wrapping OpenAI's hosted search behind our own `web_search` tool instead of handing it to the agent model
- Manual smoke test (real API, expected cost < $0.50): each of two users holds one conversation and makes one tool call; paste a summary of `llm_calls`
